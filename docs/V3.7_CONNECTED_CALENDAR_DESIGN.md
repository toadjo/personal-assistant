# v3.7.0 Connected Calendar Foundation - Revised Technical Design

## 1. Outcome and Scope

v3.7.0 adds connected calendar sync from Google Calendar and Microsoft Outlook into the existing Calendar panel.

1. External events are read-only in v3.7.0.
2. The existing Calendar panel remains the only calendar UI.
3. No email read, email send, or email signal parsing in v3.7.0.

## 2. Repo Alignment Requirements

This design follows current project patterns.

1. Database migrations use `better-sqlite3` with `db.exec(...)`.
2. Schema and TypeScript fields use camelCase, matching existing tables and shared types.
3. OAuth tokens use existing secure secret helpers (`encryptSecret`, `decryptSecret`, `isEncrypted`) plus `app_settings` storage, similar to existing AI and Home Assistant patterns.
4. IPC additions follow existing `IpcInvoke` constants, Zod schemas in `src/main/ipc/schemas.ts`, handler registration in `register-handlers.ts`, preload literal generation, and typed renderer bridge updates.
5. Outbound provider calls must pass policy and host allowlist checks.

## 3. Provider Compliance Rules

### 3.1 Google

1. Use Google Calendar API, not Gmail API.
2. OAuth flow is authorization code with PKCE for desktop public clients.
3. Scopes use least privilege:
   1. Preferred: `https://www.googleapis.com/auth/calendar.events.readonly`.
   2. Alternative if needed: `https://www.googleapis.com/auth/calendar.readonly`.
4. Incremental sync uses `nextSyncToken` from events list.
5. If events list returns HTTP `410 Gone`, clear cached events plus sync state for that account and calendar, then run full sync.
6. Do not combine `syncToken` with unsupported filters such as `timeMin` or `timeMax`.

### 3.2 Microsoft

1. Use Microsoft identity platform authorization code flow with PKCE for public client desktop app.
2. Prefer `Calendars.ReadBasic`. Use `Calendars.Read` only if required by UX fields.
3. Use Microsoft Graph `calendarView` for expanded instances across a chosen date range.
4. Keep `deltaLink` storage optional in v3.7.0. Persist only if used later.

### 3.3 Source References

1. [Google OAuth for desktop apps](https://developers.google.com/identity/protocols/oauth2/native-app)
2. [Google Calendar incremental sync](https://developers.google.com/workspace/calendar/api/guides/sync)
3. [Google Events list reference](https://developers.google.com/calendar/api/v3/reference/events/list)
4. [Microsoft OAuth authorization code with PKCE](https://learn.microsoft.com/en-us/entra/identity-platform/v2-oauth2-auth-code-flow)
5. [Microsoft Graph calendar events](https://learn.microsoft.com/en-us/graph/api/calendar-list-events?view=graph-rest-1.0)

## 6. Secure Token Storage Pattern

Store tokens in `app_settings` as encrypted strings, matching existing secret services.

### 6.1 New Service

Add `src/main/services/connectedCalendarSecrets.ts`.

```typescript
import { mainLog } from "../log";
import { deleteSetting, getSetting, setSetting } from "./settingsRepository";
import { decryptSecret, encryptSecret, isEncrypted, SecureStorageUnavailableError } from "./secureSecrets";

function tokenKey(accountId: string): string {
  return `connectedCalendar.${accountId}.tokens`;
}

export type OAuthTokenSet = {
  accessToken: string;
  refreshToken?: string;
  expiryDate?: string;
  scope?: string;
  tokenType?: string;
};

export async function saveConnectedCalendarTokens(accountId: string, tokens: OAuthTokenSet): Promise<void> {
  const now = new Date().toISOString();
  try {
    const encrypted = encryptSecret(JSON.stringify(tokens));
    setSetting(tokenKey(accountId), encrypted, now);
  } catch (error) {
    if (error instanceof SecureStorageUnavailableError) {
      throw error;
    }
    throw new Error("Failed to encrypt connected calendar tokens.");
  }
}

export async function getConnectedCalendarTokens(accountId: string): Promise<OAuthTokenSet | null> {
  const raw = getSetting(tokenKey(accountId));
  if (!raw) return null;
  if (!isEncrypted(raw)) {
    mainLog.warn("Legacy plaintext connected calendar tokens detected. Reconnect is required.");
    return null;
  }
  const decrypted = decryptSecret(raw);
  if (!decrypted) return null;
  try {
    return JSON.parse(decrypted) as OAuthTokenSet;
  } catch {
    return null;
  }
}

export function clearConnectedCalendarTokens(accountId: string): void {
  deleteSetting(tokenKey(accountId));
}
```

### 7.3 Disconnect Behavior

Disconnect operation must run as one transaction for data rows, then clear secret key.

1. Delete `connected_accounts` row.
2. Cascade deletes `external_calendar_events` and `external_calendar_sync_state`.
3. Delete encrypted token setting for that account.

## 8. Google Sync Behavior

### 8.1 Full Sync

1. Use events list with date window filters if needed.
2. Save returned events normalized.
3. Persist `nextSyncToken` per account and calendar.

### 8.2 Incremental Sync

1. Call events list with `syncToken`.
2. Do not include `timeMin`, `timeMax`, or other unsupported filters with `syncToken`.
3. Upsert active events by `(accountId, externalId)`.
4. Remove cancelled or deleted events from local cache when indicated by provider response.

### 8.3 410 Gone Recovery

If Google responds with `410` for a sync token:

1. Delete cached external events for affected account and calendar.
2. Clear sync token state for affected account and calendar.
3. Run full sync immediately.
4. Record sync state transition and `lastFullSyncAt`.

## 9. Microsoft Sync Behavior

### 9.1 v3.7.0 Behavior

1. Use `calendarView` with a bounded date window to fetch expanded instances.
2. Normalize and upsert events.
3. Remove stale local events outside current provider result for the synced window.
4. Keep `deltaLink` nullable and optional for future incremental sync phase.

### 9.2 Scope Choice

1. Prefer `Calendars.ReadBasic` if fields are title, time, location, and identifiers.
2. Move to `Calendars.Read` only if required by missing fields.
